- **핵심 약속 (1문장)**: "내가 가진 옷으로 만든 코디를, 마네킹이 입은 모습으로 한눈에 보여드립니다."
- **대표 소재 메시지**: "옷장에 100벌 있는데 매일 똑같은 옷만 입나요?"
- **주 로케일**: ko
- **감성 톤**: 공감/친근
- **비주얼 무드**: warm (크림/복숭아 — #FDEAE0, #FFF6F1 + 코랄 액센트 #E73349)
- **예상 유입 경로**: 광고 클릭 (Meta) — 중간 동기

## 고객 장면 요약 (6P)

- **도착 전 상황 (Problem)**: 옷장에 50~150벌 옷이 있는데 매일 입는 건 똑같은 10벌 안쪽. 새로 사도 비슷한 무채색만 또 사게 됨. 약속 전 30분~1시간 옷장 앞에서 헤맴. "이거랑 저거 어울리려나?"를 머릿속으로만 상상하다 결국 늘 입던 조합.
- **도착 전 감정 (Emotion)**: 답답함 + 자기 짜증("또 비슷한 거 샀네"). 무력감("어차피 안 입을 것 같아"). 조합 상상이 안 돼서 시도 자체를 포기.
- **유입 경로 (Action)**: 인스타그램/페이스북 피드 스크롤 중 "옷장에 100벌 있는데..." 후크에 클릭.
- **핵심 장애물 (Struggle)**: "머릿속으로 조합해봐도 입은 모습이 안 그려져서" 새 시도를 못 함. + "있는 옷으로 뭘 어떻게 조합해야 할지 모름".
- **결정적 기능 (Attempt)**: AI가 내 옷장 사진을 읽고 어울리는 조합을 찾아, **마네킹에 입혀서 여러 벌을 격자로** 보여줌. 상상할 필요 없이 입은 모습을 바로 확인. 새 돈 없이.
- **기대하는 해피엔딩**: 아침에 마네킹 코디 격자를 슥 훑고 마음에 드는 걸 그대로 입음. 친구가 "오늘 옷 다르네?"라고 묻는데 사실 옷장 구석에 있던 옷. 매일 새 사람처럼 보이는데 새 옷은 안 샀음.

## 감정 아크 Peak 지정

- **Peak 섹션**: SolutionSection 1 (마네킹 코디 격자 — 가장 강한 VP + 실제 마네킹 이미지 격자)
- **End 섹션**: PostCTASection

## 섹션 순서

```
[가설 종속 영역 — 단일 가설 A]
1. HeroSection (앱 다운로드 배지 → 이메일 팝업)
2. PainSection

[서비스 공통 영역]
3. SolutionSection 1: 마네킹이 입은 모습으로 코디 격자 ★ Peak
4. HowItWorksSection: 3단계 사용 흐름 ★ 신규 (옷 등록 → 마네킹 착장 → 나처럼 조절)
5. SolutionSection 2: 있는 옷에서 새 조합 발견 (옷장 활용)
6. CredibilitySection
7. TestimonialSection (인터뷰 발화)
8. ComparisonSection: StyleRoom식 2열 대조 (기존 코디앱 flat lay vs 마네킹)

[클로징]
9. PricingSection (무료/구독 비교 + 크레딧 + 앱배지 팝업) — **마지막 클로징, 가격→앱다운로드로 닫기**
10. PostCTASection (모달 완료화면이 대체 — 별도 섹션 불필요)
```

> **MVP 범위 (광고용 최소)**: Hero → Pain → Solution 1 → HowItWorks → Comparison → Pricing
> 나머지(Solution 2, Credibility, Testimonial)는 광고 집행 중 병렬 추가.

> **순서 근거 (v3.1)**: "왜 우리가 나은지(Comparison)" → "그래서 이 가격에 시작(Pricing+앱배지)" 설득 논리.
> CTASection(별도 다크 CTA)은 **제거** — Pricing이 마지막 클로징 역할을 흡수해 "부담없이 시작하세요" 중복 해소.
> Pricing이 페이지 끝이므로 클로징 강조 필요(앱 배지 주변 강조 또는 배경 톤 조정).

> **이메일 팝업 (공통 모달)**: Hero의 "무료로 시작하기" 버튼, Pricing 각 카드의 플랜 버튼 클릭 시 모달이 뜬다.
> 모달 흐름 = (플랜 선택 →) 출시 준비 안내 + 이메일 입력. PricingSection·Hero 공통.
> 제출 로직(WaitlistForm) 재사용. utm + pricing_intent(플랜) 저장.
>
> **플랜 선호 신호 (v3.1 — 플랫폼 신호 대체)**: 어느 플랜을 골랐는지(무료/구독) 기록해 지불의향을 측정.
> - 플랜 버튼 클릭 시 Amplitude `plan_selected` 발사, props `{ plan: "free" | "subscribe" }` (이메일 미등록 클릭도 잡힘)
> - 선택한 plan을 모달로 전달 → 이메일 제출 시 `waitlist.pricing_intent`에 함께 저장 (free/subscribe)
> - "구독 플랜" 클릭 비율 = 지불의향 핵심 지표 (돈 낼 의향)
> - 기존 폴(yes/maybe/no) 제거 — 플랜 선택이 더 직접적인 신호.
> - device_pref 컬럼은 이제 미사용(방치). iOS/Android 신호는 검증 단계 우선순위 낮아 포기.

## HeroSection 〈가설 종속 — A〉

**배지**: (제거 — "베타 모집중" 같은 미출시 티 제거. 본문은 출시된 서비스처럼)

**헤드라인**: "<span>내</span> 옷장에 <span>100벌</span> 있는데, 매일 똑같은 옷만?"
- 강조 (`<span>`): "내" + "100벌" — "내가 이미 가진 옷"임을 분명히 (쇼핑몰/홈쇼핑 오해 방지)
- 출처: s2-s6 카피 H1 기반 + 피드백 반영("내" 추가로 내 옷장 강조)

**서브헤드라인**: "있는 옷도 조합이 어려운 건, 입은 모습이 안 그려지기 때문이에요.
AI가 내 옷장에서 새 조합을 찾아, 마네킹이 입은 모습으로 보여드려요.
새 옷 사지 않고도, 매일 새 룩."

**CTA — "무료로 시작하기" 버튼** (v3.1 — 앱 배지 대체):
- 단일 버튼 "무료로 시작하기" (코랄, 눈에 띄게). 앱스토어 배지 제거.
- 클릭 시 → **플랜 선택 모달 오픈** (플랜 선택 → 출시 안내 + 이메일)
- "다운로드/스토어" 표현 제거 — 홈쇼핑·앱스토어 오해 방지, "내 옷장 코디"에 집중

**플랜 선택 + 이메일 모달 (공통)** — 출시 예정 고지 포함:
- **1단계 — 플랜 선택** (Hero 진입 시): "무료 플랜" / "구독 플랜" 두 버튼. 선택 시 plan 기록(Amplitude `plan_selected`).
  - (Pricing 카드 버튼으로 진입 시엔 플랜이 이미 정해져 이 단계 건너뜀)
- **2단계 — 출시 안내 + 이메일**:
  - 헤드라인: "앗, 사실 출시 준비 중이에요"
  - 안내: "곧 출시 예정이에요! 지금 이메일을 남겨두시면 출시할 때 가장 먼저 알려드리고, **코디 10개를 선물**로 드려요."
  - 이메일 입력 + "등록하고 선물 받기" 버튼
  - 제출 → WaitlistForm 로직 (utm + pricing_intent(free/subscribe) 저장)
- 폴(yes/maybe/no) 제거 — 플랜 선택이 지불의향 신호.
- ⚠️ 윤리: 본문은 출시된 톤이어도, 모달에서 "출시 준비 중" 명확히 고지 (Regret Test 통과)

**CTA 보조 텍스트**: "지금 가입 시 코디 10개 무료 🎁" (버튼 아래, 가벼운 인센티브)

**히어로 통계**:
- `3가지` / 매일 받는 새 조합 추천 / 출처: 서비스 약속
- `0원` / 옷 추가 구매 / 출처: 서비스 본질
- `30초` / 가입부터 시작까지 / 출처: 서비스 약속

**배경 스타일**: warm-light (#FDEAE0 → #FFF6F1 그라디언트)

**히어로 비주얼 명세**:
- 유형: 실제 마네킹 코디 이미지 (디바이스 목업 또는 격자 카드)
- 내용: 마네킹이 코디를 입은 이미지 1~3장을 겹쳐 배치하거나, 핸드폰 프레임 안에 격자로 표시. "내 옷장 그대로 · 입은 모습" 태그.
- 에셋 현황: **✅ 확보** — 여성 마네킹 코디 10장 (GPT 4장 세로 + 나노바나나 6장). claude.ai에서 제작·검증 완료
- 제작 방법: 확보한 이미지를 `web/public/mockup/`에 배치. 대표 1장 크게 + 보조 2장 겹침, 또는 폰 프레임 안 격자
- 대체안: (불필요 — 에셋 확보됨)

**보조 CTA**: 없음 (단일 CTA로 집중)

**BMAP 분석**:
- **Motivation**: 광고 클릭 → 중간 동기. "100벌" 구체 숫자로 즉시 자기 인식 강화
- **Ability 장벽**: 스크롤 없이 핵심 약속(가진 옷 + 입은 모습 코디)이 보여야 함. CTA 버튼이 첫 화면에
- **Prompt**: CTA 버튼은 코랄(#E73349)로 강한 대비. "카드 필요 없음"으로 마찰 제거

## PainSection 〈가설 종속 — A〉

**배경**: light-warm (#FFF6F1)

**섹션 타이틀**: "이런 경험, 매일 하고 있지 않나요?"

**심리 원리**: 바넘 효과 — 인터뷰 B/C 발화를 그대로 옮겨 "어, 내 얘기네" 만들기

**Pain Points**:

1. **수치**: "90벌"
   **제목**: "매일 똑같은 10벌만 입어요"
   **설명**: "옷장은 가득한데, 구석 옷은 있는지도 모르고 매일 같은 자리에 손이 가요."
   **퍼소나 근거**: B "구석에 있는 옷은 있는지도 모르고" + C "막상 보면 새로운 게 있어요"

## PricingSection 〈서비스 공통〉 ★ 신규 — 지불의향 측정

**심리 원리**: 앵커링 + 부담 제거. 무료로 할 수 있는 게 충분함을 보여주고, 유료는 "더 필요할 때"로 가볍게.

**타이틀**: "부담 없이 시작하세요"

**서브텍스트**: "대부분의 기능은 무료예요. 가입만 해도 코디 10개를 선물로 드려요."

**가격 표시 — 무료/구독 2열 비교 카드 + 크레딧 별도 안내**:

크레딧(낱개 구매)과 구독(옷장 용량)은 **별개 축**이다. 카드는 무료 vs 구독으로, 크레딧은 카드 아래 별도 줄로 표기.

**무료 요금제**
- 가입 선물: 코디 10개 즉시 지급
- 매달 무료 코디 5개 (크레딧 1개)
- 내 옷장 100벌까지
- 마네킹 코디 + 격자뷰

**구독 요금제 (월 3,900원)** — "무료의 모든 기능 +" 방식으로 표기 (무료 기능 일일이 반복 X)
- **무료의 모든 기능 +**
- 옷장 무제한
- 매달 크레딧 1개 보너스
- 광고 없음

**크레딧 (카드 아래 별도 줄 — 구독과 무관, 누구나 낱개 구매)**:
> "코디가 더 필요하면? **크레딧 1개(코디 5개) 500원** — 무료·구독 상관없이 누구나 충전"

- 무료 열 기본 강조(대부분 무료로 가능), 구독 열은 "더 필요할 때"
- 카드 상단 코랄 액센트 바
- ⚠️ **크레딧 ≠ 구독**: 크레딧은 낱개 결제(사용량), 구독은 옷장 용량(월정액). 별개로 표현해 혼동 방지. 크레딧 줄을 유료 열 안에 가두지 말 것.

**CTA — 각 카드 하단 버튼 (플랜 신호)**:
- **무료 카드 하단**: "무료로 시작하기" 버튼 → 모달(플랜=free 선택된 채 이메일 단계로 직행)
- **구독 카드 하단**: "구독 시작하기" 버튼 → 모달(플랜=subscribe 선택된 채 이메일 단계로 직행)
- 각 버튼 클릭 시 Amplitude `plan_selected` 발사(plan: free/subscribe). Pricing은 카드가 플랜을 결정하므로 모달의 플랜 선택 단계 건너뜀.
- ⚠️ 인라인 폴/이메일 폼 없음 — 버튼이 모달 트리거. 이메일은 모달 안에서만.

**지불의향 측정 (플랜 선택)**:
- 어느 플랜 버튼을 눌렀는지(무료/구독)가 지불의향 신호. "구독 시작하기" 클릭 = 돈 낼 의향.
- Amplitude `plan_selected` + Supabase `pricing_intent`(free/subscribe) 저장.
- 기존 폴(yes/maybe/no) 제거.

**비주얼 명세**:
- 유형: 무료/구독 2열 비교 카드(각 카드 하단 버튼) + 크레딧 별도 줄

## CTASection 〈가설 종속 — A〉

**배경**: dark (#1A1410 — warm-dark)

**심리 원리**: 마찰 제거 + 부담 없는 제안

**타이틀**: "부담 없이 시작하세요"

**서브텍스트**: "내 옷장이 매일 새로워지는 경험, 지금 시작해보세요. 앱을 받으면 코디 10개를 무료로 드려요."

**사회적 증거** (CTA 직전): **제외** (옵션 D — 동적 카운터 미도입. 한 자릿수 카운트 역효과 회피)

**주요 CTA — 앱 다운로드 배지** (v3): App Store + Google Play 배지 2개. 클릭 시 → Hero와 동일한 **이메일 등록 팝업(모달)** 오픈.
- 배지 보조 문구: **없음** (Hero와 동일 — 미출시 티 제거. 클릭 시 팝업에서 출시 예정 고지)

**보조 CTA**: 없음 (단일 행동 집중)

**면책 텍스트**: "앱은 출시 준비 중이에요. 이메일 외 어떤 정보도 받지 않으며, 출시 안내 메일만 1회 발송됩니다. 언제든 해지 가능."

**BMAP 분석**:
- **Motivation**: 여기까지 스크롤한 사용자는 동기 높음. "잃지 않게" 즉시 폼 표시
- **Ability**: 이메일 1개만 (필드 1개), utm 자동 수집
- **Prompt**: "(30초)" 시간 명시로 부담 제거

## PostCTASection 〈가설 종속 — A〉

> **Store 단계**: CTA 클릭 후 경험이 전체 브랜드 인상을 결정 (Peak-End Rule "End").

**페이지 유형**: 인라인 확인 메시지 (페이지 전환 X)

**확인 메시지**: "등록 완료! 출시되면 가장 먼저 알려드릴게요."

**안심 요소**:
- "정식 출시 전, 딱 1번 안내 메일만 보내드려요."
- "언제든 구독을 해지하실 수 있어요."

**다음 단계 안내**:
- "출시되면 가입 즉시 코디 10개를 무료로 받으실 수 있어요. 잊지 마세요!"

**감동 요소 (Delighter)**:
- "기다리는 동안 — 옷장 사진을 미리 정리해두면 가입 후 바로 코디를 받아볼 수 있어요."

**기대 설정**:
- 응답 시간: "정식 출시 시점에 안내"
- 연락 수단: "이메일"

## B.I.A.S 페이지 전체 체크

**Block**: ✅ Hero 1초 내 "100벌" 자기 인식 / CTA 단일 / Hero→Pain 배경 전환(warm-light→light-warm) / Solution 시각 변화(격자→옷장그리드)
**Interpret**: ✅ 타이틀 모두 혜택 먼저 / Pain 수치 앵커링(90벌·상상불가) → Solution 대조 / 본문 3줄·불릿 3개 준수 / 손실 회피(잠든 옷 = 잃은 자산)
**Act**: ✅ CTA 1개 행동 수렴 / 폼 필드 1개(이메일) / "(30초)·카드 불필요" 마찰 제거 / 거짓 희소성 없음
**Store**: ✅ 인라인 확인 메시지 / 안심 요소(1회 메일·해지 가능) / 다음 단계(코디 10개 무료) / 감동 요소(미리 정리)

## 윤리 체크

**Regret Test**: ✅ 헤드라인 약속 = 실제 기능. 가격(코디 10개 무료·크레딧 500원) = 확정 모델. 본문은 출시된 톤, 등록 팝업에서 "출시 준비 중" 고지로 오인 방지
**Black Mirror Test**: ✅ Pain 묘사가 불안 마케팅 수준 아님(공감 수준). 경쟁사 실명 비방 없음(flat lay 사실 대조만)
**In Real-Life Test**: ✅ 전체 톤 "도와주는 전문가". CTA "제안". 면책 진정성 있음
