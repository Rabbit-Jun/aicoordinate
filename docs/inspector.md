# 검증 차원 (가중치 순서 — 위가 가장 엄격)

## ① 결론-근거 일치 [최우선 · BLOCK 대상]
각 ✅/△/❌ 판정과 "파이프라인 결론"을 하나씩 뜯어, **표/본문의 근거가 그 결론을 실제로 뒷받침하는지** 검사한다. 다음을 잡아낸다:
- 근거는 △(조건부)인데 결론은 ✅로 격상된 경우
- "가능"이라 적었지만 출처가 그 능력을 직접 보장하지 않는 경우(인접 기능을 확대해석)
- 파이프라인 "n순위 후보" 선정 이유가 표의 학습 필요/무게/커버리지와 어긋나는 경우
- 출처 링크가 본문 주장과 다른 내용을 가리키는 경우(링크-주장 불일치)
- 과장(must/항상/완벽)·비약(A 되니까 B도 당연히) 표현
→ 각 항목을 **[근거 위치] → [결론 위치] → 불일치 사유 → 수정 제안** 형태로 적는다.

## ② 출처 신뢰성·최신성 [WARN]
- 공식 1차 문서가 아닌 출처(블로그·튜토리얼)가 근거로 쓰였는가
- 링크 누락된 능력 주장이 있는가
- 조사 기준일 기준 구버전/폐기된 기능을 현재형으로 적었는가

## ③ 누락된 대안 [WARN]
- 해당 능력에서 명백히 유력한데 표에서 빠진 기술/경로가 있는가(있다면 무엇, 왜 중요한지)

## ④ 범위 이탈 [INFO]
- 구현 공수·비용·정확도 실측 등 "범위 밖" 내용이 본문 결론에 섞였는가(→ '다음 검증'으로 내려야 함)
